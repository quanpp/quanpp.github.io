从跨域到上线：把 Node 项目跑到互联网上

发表于2026-11-14|更新于2026-11-15|技术
|浏览量:

Node 全栈系列最后一篇。接口全写完了，但还只活在 localhost:3000 上。这篇解决两件事：为什么浏览器不让你的前端调你的后端，以及怎么把这个项目真正跑到公网上。学完你会知道：同源策略到底拦的是什么、开发代理和 Nginx 代理为什么各要配一遍、cors() 为什么必须写在路由之前、表名大小写在 Linux 上为什么会炸、dotenv 为什么必须在第一行、.env 和 .env.example 怎么分工、SSH 密钥登录比密码强在哪、宝塔面板怎么把部署门槛降下来、PM2 是干什么的，以及改完代码为什么必须重启。

一、跨域：浏览器在拦你

1.1 同源策略

接口用 Apifox 调得好好的，一放到页面里就报错：

原因是同源策略：浏览器只允许脚本读取同源的资源。

同源的定义是三项全等：

项 例子
协议 http / https
域名 localhost / api.xxx.com
端口 3000 / 63342

页面在 63342，接口在 3000——协议域名都一样，端口不同，所以算跨域。

注意：跨域是浏览器的限制，不是服务器的限制。 所以 Postman、Apifox、curl 调同一个接口完全没问题——它们不执行同源策略。这也是”Apifox 能通、页面报错”的原因。

这条规则是为了防止恶意站点读取你在其他网站的数据。但它把自家前后端也一起挡在门外了。

1.2 三种解法

方案 做法 用在哪
开发服务器代理 前端 vite.config.js 里配 proxy 只有开发环境
Nginx 反向代理 服务器上配转发规则 只有生产环境
CORS 后端响应头声明允许的源 开发生产通用

为什么推荐 CORS？

代理方案的死穴是要配两遍：开发用 Vite 代理，上线用 Nginx 代理，两套配置两处维护。更糟的是，上线时忘了配 Nginx，接口全 404——前端说后端没部署好，后端说前端没配代理，一件小事能扯一周。

CORS 是后端加一行代码，开发和上线都生效，不存在”忘配”的问题。

1.3 CORS 怎么用

位置很关键。 中间件是按注册顺序执行的，写在路由后面，请求已经进业务逻辑了，响应头加不上。

二、几个容易卡住的问题

2.1 表名大小写：本地能跑，上线就炸

Sequelize 的默认约定：模型单数，表名复数。

问题出在大小写：

环境 表名实际长什么样
Docker 跑 MySQL articles（全小写）
Windows 装 MySQL Articles（首字母大写）
Linux 装 MySQL 严格区分大小写

Linux 上的 MySQL 默认 lower_case_table_names=0，表名大小写敏感。 本地在 Windows 上跑得好好的，代码里写 Articles，服务器上表叫 articles，直接报 Table doesn't exist。

三种解法：

  1. 部署时重跑一次迁移（推荐）——迁移文件里写的是 Articles，服务器上建出来就是 Articles
  2. 把导出的 SQL 表名统一改大小写再导入
  3. 在 MySQL 配置里改 lower_case_table_names——但初始化之后改不了，只能重装

这就是第一篇说”表名统一首字母大写 + 复数”的原因。不是为了好看，是为了少一个只在服务器上出现的 bug。

2.2 迁移和种子：不是必须，但值得

手动建表也能跑，只要字段命名对得上。但迁移有三个好处：

好处 说明
交付干净 不用附 SQL 文件，对方跑一条命令就建好表
团队一致 改字段提交迁移文件，别人拉下来执行，结构完全一样
部署省事 服务器上跑 db:migrate 就更新了，不用远程连库手改

种子解决”别人拿到项目跑起来是空库”的问题：系统设置、初始管理员、测试数据，一条命令全灌进去。

2.3 接管已有的表

接手老项目，表名是 clwy_posts，外键叫 category_id，还没有时间戳字段——和 Sequelize 的默认约定全都不符。

三、上线前的收尾

功能写完不等于项目完成。这几件事决定”别人拿到能不能跑起来”。

3.1 端口别写死

一台服务器部署多个项目时，全都挤在 3000 必然冲突。改配置，别改代码。

3.2 .env 和 .env.example

.env 里有数据库密码、JWT 密钥，绝不能进仓库。但别人拿到项目，又必须知道要配哪些变量。

做法是复制一份模板，把敏感值清空：

原则一句话：可以让人知道的一律保留，不能让人知道的全部删掉。 变量名、默认值、注释留着，密钥留空。

3.3 README 要能让陌生人跑起来

最低要求五项：

  1. 项目简介、技术栈
  2. 环境变量怎么配、密钥怎么生成
  3. 数据库怎么建、怎么迁移、怎么灌种子
  4. 装依赖和启动的命令
  5. 访问地址、初始管理员账号

写的时候注意：命令别带反斜杠换行，复制出去会执行失败。

3.4 .gitignore 先写再 init

四类东西不该进仓库：

排除 原因
node_modules/ 靠 package.json 能还原，几百 MB
.env 有密钥
编辑器配置 和项目无关
本地数据文件 运行产物

⚠️ 先写 .gitignore 再 git init。 顺序反了，node_modules 已经被 add 进去，后面再加规则也删不掉（要从索引里 remove）。

3.5 一个致命顺序问题

dotenv 必须在所有 require 之前。 因为模块加载时就会读取 process.env，配置还没加载，读到的全是 undefined——JWT 密钥是 undefined，签出来的 token 验不过。

这个坑只在部署时暴露（本地因为别的原因可能刚好能跑），排查起来极费时间。

四、买服务器和域名

4.1 配置怎么选

用途 CPU 内存 带宽
个人项目、练手 1 核 2 GB 2 M
企业常规 2 核 4 GB 3–5 M

个人项目 1 核 2 G 足够。企业项目别省——MySQL 和 Node 抢内存，2 G 会频繁 OOM。

4.2 系统选 Linux

Windows Server Linux
授权费 要买 免费
稳定性 常靠重启恢复 能几年不重启
远程管理 远程桌面吃带宽 SSH，流量极小

服务器只能远程操作，图形桌面在弱网下几乎没法用。

发行版选 Ubuntu 22.04 LTS 或 Debian。别用 CentOS——已经停止维护了。

4.3 备案：国内服务器绕不过去

服务器在国内，域名必须备案才能对外访问。 境外或香港免备案，但服务国内用户不稳定。

流程六步（全程免费）：

  1. 填主体信息（个人还是公司）
  2. 申请备案服务码（每台服务器 5 个）
  3. 提交网站信息，扫码人脸识别
  4. 厂商初审（当天电话核实）
  5. 工信部短信验证
  6. 管局终审（几天到一个月）

备案要提前做。 项目写完了才发现要等一个月，很被动。

5.3 换成密钥登录

密码可以被暴力破解——一直试总有撞对的。密钥对则是：私钥留本机，公钥放服务器，两边配对才能进，猜不出来。

总结

全系列最后一篇，主干六条：

  1. 跨域是浏览器的限制，所以 Apifox 能通、页面报错；CORS 是唯一”配一次管两端”的解法，app.use(cors()) 必须在路由之前
  2. 表名大小写只在 Linux 上炸：统一首字母大写 + 复数，部署时重跑迁移，能省掉一个只在生产出现的 bug
  3. dotenv 必须在第一行，否则密钥读到 undefined，token 签出来验不过——这个坑只在部署时暴露
  4. .env 不进仓库，.env.example 进：变量名留着，密钥清空；生产的 SECRET 必须和开发不同
  5. node_modules 绝不跨平台传输，原生模块的二进制不兼容，必须在服务器上重新装
  6. git pull 之后必须重启：Node 进程加载的是内存里的代码，文件换了它不知道
