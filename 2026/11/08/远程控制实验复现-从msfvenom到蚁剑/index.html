远程控制实验复现：从 msfvenom 反向 Shell 到一句话木马

发表于2026-11-08|更新于2026-11-08|技术
|浏览量:

一次课程实验的完整复现。作业只有两行字：复现 PPT9-10 的对被控端控制并把生成的 exe 提交微步云沙箱检测；往目标网站写入一句话木马，用蚁剑连接控制，主要步骤截图。看着简单，实际卡住人的全是环境细节。这篇按「反向 Shell → 沙箱检测 → Webshell」的顺序走一遍，把踩过的三个坑和一句话木马的关键区别记下来。

全部操作在自有虚拟机与本机 phpstudy 环境完成，截图中的 MAC 地址、内网 IP、IPv6 地址、系统用户名均已做马赛克处理。本文仅用于课程学习与授权范围内的实验记录。

一、先摆正几个概念

远程控制程序按连接方向分两类：

  • 正向连接：攻击者主动去连目标上开着的端口。目标在 NAT 后面、或者防火墙挡入站时基本没戏。
  • 反向连接：被控端主动回连攻击者。出站流量通常放行，所以现实里几乎都用这个。本次用的 windows/meterpreter/reverse_tcp 就是反向。

另外几个容易混的词：Shell 是命令解析器（如 cmd.exe）；Shellcode 是利用漏洞时执行的十六进制机器码，因为常用来拿 shell 而得名；Webshell 是上传到网站的网页后门脚本，用于 Web 渗透里的权限维持；一句话木马 则是 Webshell 的最短形态，一行 PHP 就够。

上一章的 vsftpd 2.3.4 笑脸后门是「漏洞 → 6200 端口 root shell」，属于小入口直接变远程控制。这次两条链路分别是「可执行 payload」和「网页脚本」，入口不同，本质都一样。

二、实验一：msfvenom 生成被控端 + 主控端接管

环境

角色 环境 说明
攻击机 Kali Linux Metasploit Framework，与靶机同网段
被控端 Windows 10 关闭防火墙与 Defender 实时保护
网络 同一 NAT 网段 双方互 ping 通是前提

生成 payload

-p 指定 payload，-f 指定输出格式，-o 指定保存路径；LHOST / LPORT 是回连地址和端口，由 payload 编译时写死进 exe。输出里 No encoder specified, outputting raw payload、Final size of exe file: 7168 bytes 说明这是没做任何免杀的原始载荷。

坑一：LHOST 抄了课件里的 IP

课件截图上的地址是老师当时那套网段的，照抄过去 exe 会回连到一个不存在的地址，现象是「双击没反应、Kali 一直空等」。LHOST 必须填 ip a 查出来的本机当前 IP，且每次换网络都要重新生成 exe。

坑二：python3 -m http.server 报 404

这个命令只服务当前工作目录。我在 /home/kali 下起的服务器，payload 却存在 /root/，浏览器访问 /payload.exe 自然 404。两种改法：

先打开 http://<Kali的IP>:8000/ 确认目录列表里能看到 payload.exe，再下载。

坑三：命令敲在 msfconsole 启动之前

一次性把 msfconsole 和后面几行 set 全粘进终端，结果 Metasploit 的 banner 在这些命令之后才打印出来 —— 说明它们被当成启动前的输入吞掉了，一条都没生效。判断依据很简单：干净的 msf > 提示符，中间没有 payload =>、lhost => 的回显，也没有 Started reverse TCP handler。

三、实验二：微步云沙箱检测

把同一个 payload.exe 提交到 微步云沙箱 跑动态分析。

报告里值得看的几处：

  • 引擎检出 11/28 判恶意，木马家族标记为 Agent；
  • 多维检测命中 Sigma 规则 PExEc Service Start、PExEc Tool Execution —— 对应 meterpreter stageless 载荷落地后的典型行为；
  • 网络行为里能看到对 LHOST:5000 的回连，这是把它和「普通可疑 exe」区分开的关键证据，也正好反向验证了上一节 LHOST 确实写进了文件。

检出率高是意料之中：7 KB 的 raw payload、无编码器、无壳、无混淆，特征库里早就有了。作业复现不需要加 -e 做免杀，加了反而和课堂现象对不上。

四、实验三：一句话木马 + 蚁剑

为什么课件那句话蚁剑连不上

PPT 第 7 页给的是：

它适合浏览器直接访问 shell.php?cmd=ipconfig，system() 把参数当系统命令执行并回显。但蚁剑的工作方式是把一段 PHP 代码 POST 过去，让目标站点执行再把结果带回来 —— 没有 eval()，这段代码只会被当字符串丢给 system()，自然连不上。这是「一句话木马」和「能接蚁剑的 WebShell」之间最容易忽略的区别。

用一行同时兼容两种用途：

$_POST['cmd'] 给蚁剑，$_GET['cmd'] 留给浏览器验证，互不干扰。把文件放进 phpstudy 的网站根目录（一般是 WWW/）即为「写入目标网站」。

蚁剑连接参数

项 值
URL http://127.0.0.1/shell.php
连接密码 cmd（即 $_POST 的参数名）
连接类型 PHP
编码器 default，连不上再试 base64

测试连接通过后进入文件管理，能看到站点目录和刚放进去的 shell.php；虚拟终端执行 whoami、dir 有回显，说明已经能通过 Web 脚本操作这台服务器。

关于满屏方块乱码：那是 Windows ipconfig 输出 GBK 编码、浏览器/蚁剑按 UTF-8 渲染导致的，不是打码也不是命令失败。蚁剑虚拟终端把编码切成 GBK 即可，或者干脆用 dir、ver 这类不含中文的命令做验证。

五、截图脱敏：哪些信息真的要遮

课程截图发公开博客前，值得处理的其实是这几类：

  • MAC 地址：ipconfig 不带 /all 不显示物理地址，但 ip a 的 link/ether 那一行会直接给出，本文第一张图里就有，必须遮。
  • IPv6 链路本地地址：fe80:: 开头的地址常由 MAC 经 EUI-64 生成，能反推物理地址，别因为「不是 MAC」就留着。
  • 内网 IP、会话时间戳：单独看风险不大，但组合起来能还原实验拓扑，顺手遮掉。
  • 系统用户名：whoami 的回显最容易关联到本人，尤其账户名和姓名/学号相关时。

更省事的做法是从源头避免：验证「能执行命令」根本不需要 ipconfig，用 dir、ver 就够了，回显明显且零敏感信息。遮得太多反而让老师/读者看不出这一步做成了什么，保留命令本身和关键结果就行。

六、收尾

实验结束依次清理：sessions -K 关掉会话、蚁剑里删除 shell 条目、删掉 WWW/shell.php、停掉 Apache 和 http.server、删除 payload.exe。留着一句话木马在 Web 根目录是很危险的习惯，哪怕是自己本机。

三个实验串起来其实就一条线：小入口 → 远程控制。6200 后门、回连 5000 端口的 exe、写在网站目录里的一行 PHP，入口形态完全不同，但拿到控制权的判断标准始终一致 —— 能不能在目标上执行命令并看到回显。

本文所有操作仅限自有实验环境，涉及的 IP、MAC、用户名均已脱敏，请勿用于未授权的测试。
