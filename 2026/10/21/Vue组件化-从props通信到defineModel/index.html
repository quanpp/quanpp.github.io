Vue 组件化：从 props 通信到 defineModel

发表于2026-10-21|更新于2026-10-21|技术
|浏览量:

Vue 系列第二篇。上一篇把模板和数据讲完，这篇解决组件之间怎么打交道：Vue3 组合式 API 为主，Vue2 选项式对照。学完你会知道：props 校验的完整写法、单向数据流为什么不能反向改 props、v-model 在自定义组件上的本质、defineModel 替你省掉了哪些样板代码、四种插槽分别解决什么问题、自定义指令的钩子两代怎么映射、为什么改完数据不能马上操作 DOM。文末附通信方式总览和四张速查表。

一、组件基础：三部分和两种注册

1.1 单文件组件的三部分

一个 .vue 文件 = template + script + style：

根组件是 App.vue，整个应用从它开始渲染，挂在入口 HTML 的挂载点上，其他组件都是它的子孙。

<script setup> 里想给组件定义 name 这类选项，用 Vue 3.3 引入的 defineOptions({ name: 'MyComp' }) 宏，不用再另起一个普通 <script> 标签。

1.2 两种注册方式

局部注册 全局注册
Vue2 写法 components: { 组件名 } 选项 Vue.component('组件名', 组件)
Vue3 写法 <script setup> 里 import 即用 app.component('组件名', 组件)
作用范围 只在当前组件可用 所有组件可用
代价 用谁引谁 所有组件都能用，但名字容易冲突、增加包体积

日常开发用局部注册，只有轮播图、对话框这种到处都用的基础组件才值得全局注册。

1.3 两个必须记住的坑

坑一：data 必须写成函数。

写成对象（data: { count: 0 }）会导致所有组件实例共享同一份数据，一个组件改了，其他组件跟着变。函数每次被调用都返回新对象，实例之间互不干扰。

坑二：scoped 解决样式冲突。

不加 scoped，所有组件的样式默认全局生效，容易改到别人的样式。加上 scoped，编译时给元素加一个唯一属性选择器（如 [data-v-7ba5bd90]），样式只作用于本组件。

⚠️ scoped 的“漏网之鱼”：子组件根节点会同时被打上父组件的 scoped 标识，所以父组件能影响子组件根节点的样式；反过来，父组件样式默认影响不到子组件内部——要穿透，用 :deep()。

二、父子通信：props

2.1 父传子：属性绑定 + props 接收

props 可以传任意数量、任意类型（数字、布尔、对象、数组都行）。

2.2 props 校验

数组写法省事但没保障，正式项目用对象完整写法：

三个注意点：

  1. 类型不符、必填缺失，控制台会有错误提示——这就是校验的价值，帮你快速定位传错的地方
  2. default 和 required 一般不同时写：必填项肯定有值，写默认值没意义
  3. default 是复杂类型（对象、数组）时，必须以工厂函数形式返回：default: () => []

2.3 单向数据流：子组件不能改 props

Vue2 时代就定下的规矩，Vue3 一样：

  • 父组件的数据通过 props 流进子组件，子组件可以用，但不能直接改
  • 想让数据变，子组件 $emit 通知父组件，由父组件来改

一句话口诀：props 只读，要改让爹改。（progress 组件收到 w 值只负责渲染宽度，想动态改宽度，得子组件发事件、父组件改数据。）

⚠️ 注意 Vue2 到 Vue3 的一个细节变化：Vue2 里直接改 props，视图可能还是会更新（只是不推荐）；Vue3 中 props 是只读的响应式代理，修改会直接抛警告。

3.4 历史遗迹：.sync

Vue2 的 .sync 修饰符是“更新指定属性”的语法糖：<child :title.sync="pageTitle" /> 等价于监听 update:title 事件。Vue3 把它合并进了 v-model:title 的写法，.sync 已被移除，读老代码见到知道是什么就行。

四、跨层通信和其他方式

4.1 provide / inject：跨层传递

  • 传响应式数据时，provide 一个 ref/reactive 对象，底层组件拿到的还是响应式的，改了会同步

ECharts 图表容器这类“必须拿到真实 DOM”的场景就用它。Vue2 对应 this.$refs.xxx。

4.3 已淘汰的 event bus

笔记里的 Vue2 “事件总线”（一个空的 Vue 实例当全局 $on/$emit 中转站）Vue3 已移除这三个 API，新项目别用了。跨组件事件用 mitt 这种小库，或者干脆上 Pinia（第三篇讲）。

六、自定义指令：两代钩子对照

6.1 注册和使用

注册时不加 v- 前缀，使用时加。

6.2 钩子函数两代对照

Vue2 Vue3 时机
bind beforeMount 指令第一次绑到元素上
inserted mounted 元素插入父节点
update updated 所在组件更新
componentUpdated updated 所在组件及其子组件更新完
unbind unmounted 指令与元素解绑

Vue3 把 componentUpdated 合并进了 updated，并统一了命名（和生命周期钩子一样加 on 风格的动词）。钩子参数没变：(el, binding)，binding.value 拿指令值、binding.arg 拿参数、binding.modifiers 拿修饰符。

6.3 案例：v-loading 的封装思路

请求没回来时页面一片空白，体验差。封装一个 loading 指令：

  1. mounted 和 updated 时判断 binding.value：为 true 就创建一个全屏遮罩 DOM 盖上去，为 false 就移除
  2. 指令值变化会触发 updated，自动切换遮罩
  3. 用的时候 <div v-loading="isLoading">内容区</div>，请求前后翻转一个变量就完事

这就是自定义指令的价值：把重复的 DOM 操作收进一个指令。

七、$nextTick：DOM 是异步更新的

经典场景：点“编辑”显示输入框，然后立刻让输入框获取焦点。

总结

组件篇的主干：

  1. 注册：局部优先，全局只给基础组件；data 必须是函数，scoped 管样式
  2. props：校验四件套（type/required/default/validator），单向数据流——子不能改 props，要改 emit 上报
  3. v-model：组件上 = prop + 事件，Vue3 换成 modelValue；defineModel 一行搞定双向绑定
  4. 通信选型：跨层用 provide/inject，拿 DOM 用 ref，共享状态上 Pinia；event bus 和 .sync 都是历史
  5. 插槽：默认、具名、作用域，两代通用；作用域插槽是能力不是分类
  6. 两个易忘点：自定义指令钩子改名了一半，$nextTick 等的是 DOM 更新
