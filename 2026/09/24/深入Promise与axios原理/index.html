一、为什么需要 Promise：回调地狱

二、Promise 是什么

一句话：Promise 是一个管理异步操作的对象，它会告诉你这个异步操作成功了还是失败了。

2.2 三种状态

每个 Promise 必然处于三种状态之一：

状态 含义 触发
pending（待定） 初始状态，任务进行中 new Promise 后默认
fulfilled（已兑现） 成功 调 resolve()
rejected（已拒绝） 失败 调 reject() 或代码报错

两条死规则：

  1. 状态只能从 pending → fulfilled 或 pending → rejected，一旦改变就不可逆
  2. resolve 和 reject 只生效一个（先调的那个）

如果你 new Promise(() => {}) 忘了调 resolve/reject，状态永远是 pending，then 里的代码永远不会执行。

五、async / await：最优雅的写法

链式调用已经很好了，但 async/await 让异步代码写起来像同步代码一样直观。

5.1 基本用法

5.2 两条铁律

  1. await 必须写在 async 函数里面
  2. await 会原地等待获取 Promise 成功的结果，拿到结果才往下走

5.4 async 函数的返回值

async 函数永远返回 Promise：

  • return 123 → 返回成功状态的 Promise，值为 123
  • return new Promise(...) → 由那个 Promise 的结果决定
  • throw new Error(...) → 返回失败状态的 Promise

六、事件循环(EventLoop)：JS 怎么安排代码执行顺序

6.1 同步 vs 异步

  • 同步代码：逐行执行，原地等上一个代码执行完毕，再往下走
  • 异步代码：调用后不等，继续往下跑，完成后用回调通知你

JS 中常见的异步代码：setTimeout、setInterval、js事件绑定（如点击事件）、AJAX 请求。

6.2 为什么需要事件循环

JS 是单线程的，同一时刻只能执行一行代码。如果一行代码卡住了（比如网络请求），后面的代码就全等着。所以 JS 设计了事件循环机制：

  1. 同步代码放入调用栈，从上到下执行
  2. 遇到异步代码，交给宿主浏览器/API 去处理，不阻塞主线程
  3. 异步任务完成后，回调函数放入任务队列排队
  4. 调用栈空了，EventLoop 去任务队列取回调执行

6.3 宏任务与微任务

ES6 引入 Promise 后，异步任务分了两类：（就是把任务队列分成宏任务队列和微任务队列）

宏任务 微任务
谁执行 浏览器环境，再去宏任务队列 JS 引擎，直接进入微任务队列，更接近js逻辑
包含 setTimeout、setInterval、AJAX完成、DOM事件 Promise.then() 的回调，注意promise本身是同步的
优先级 每轮只取一个 每轮全部清空

执行规则（必背）：

  1. 先把所有同步代码跑完
  2. 清空所有微任务队列
  3. 从宏任务队列取一个执行
  4. 执行完再清空所有微任务
  5. 再取下一个宏任务……循环

一句话：微任务永远比下一个宏任务先执行。

6.4 经典面试题

答案：1 → 4 → 3 → 2

推理：

  1. 同步代码先跑：打印 1、4
  2. 同步跑完，清空微任务：Promise.then 打印 3
  3. 取一个宏任务：setTimeout 打印 2

九、常见易错点

  1. 忘了 resolve/reject：new Promise 里不调，then 永远不执行
  2. await 不在 async 里：语法错误
  3. async 函数忘了调用：定义了不执行，里面的代码不会跑
  4. 没加 try/catch：await 的 Promise 失败了会变成未捕获异常
  5. 以为 setTimeout(0) 马上执行：它是宏任务，要等所有同步代码和微任务跑完
  6. Promise.all 一个失败全挂：需要部分成功也显示的话用 Promise.allSettled

总结

概念 一句话
Promise 管理异步操作状态的对象，解决回调地狱
三种状态 pending → fulfilled / rejected，不可逆
then 接收成功结果，返回新 Promise 可链式调用
catch 统一捕获错误
async/await 用同步写法写异步代码，await 必须在 async 里
事件循环 同步 → 清空微任务 → 取一个宏任务 → 循环
宏任务 vs 微任务 setTimeout 是宏，Promise.then 是微；微任务优先
Promise.all 合并多个 Promise，全成功才进 then
axios XHR + Promise 的封装
