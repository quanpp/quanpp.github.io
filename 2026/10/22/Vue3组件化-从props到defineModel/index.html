一、组件是什么：从”一坨 HTML”到可复用的零件

1.1 为什么要拆组件

一个首页写下来，template 里三百行：轮播、商品卡片重复六遍、分页、侧边栏。问题不是长，是改不动：

  • 商品卡片要加个”包邮”标签，六处代码全改一遍
  • 轮播的样式改了，可能顺手影响了别处的 .swiper
  • 新页面也要商品卡片，只能复制粘贴

组件的本质是把”结构 + 样式 + 逻辑”打包成一个可复用的单元。拆完之后：

一屏读完，每个零件单独维护。

1.2 单文件组件的三部分

三块各管一件事，编译后变成一个组件对象。<script setup> 里的顶层声明自动暴露给模板，不用 return。

Vue3 的模板允许多个根节点（Fragment），Vue2 只能有一个。这一条改动看着小，实际省掉了大量无意义的包裹 div。

4.2 什么都能传

数字、字符串、布尔、对象、数组、函数，甚至另一个组件的插槽内容：

属性名在模板里建议用 kebab-case（:is-vip），在子组件里用 camelCase（isVip）。HTML 属性不区分大小写，写 :isVip 在某些场景会被转成 isvip，全小写就对不上了。

4.3 校验：数组写法 vs 对象写法

数组写法省事，但没有保障。正式项目用对象完整写法：

四个字段的用法：

required 和 default 为什么不同时写？必填意味着一定有值，默认值永远用不上，写了是自相矛盾。

4.6 单向数据流：props 只能读

这条规矩 Vue2 就定了，Vue3 执行得更严：

  • 父组件的数据通过 props 流进子组件
  • 子组件可以用，但不能直接改
  • 想让数据变，子组件发事件通知父组件，由父组件来改

⚠️ Vue2 里直接改 props，视图可能还是会更新（只是不推荐）；Vue3 里 props 是只读的响应式代理，改它直接报警告。

为什么要这么设计？因为一个数据可能传给多个子组件。如果子组件能改，那就变成”谁最后改谁说了算”，父组件根本不知道数据什么时候变了，出问题无从排查。数据只有一个来源，改动只有一个入口。

一句话口诀：props 只读，要改让爹改。

八、ref：拿 DOM 和拿子组件

8.1 先分清两个 ref

这一节最容易懵，因为 ref 这个词在这里有两个完全不同的角色：

写法 是什么
模板里的 ref="inp" 一个属性，给标签起个外号
script 里的 const inp = ref(null) 一个响应式变量，用来接住这个标签

配对规则只有一条：两边名字一模一样。Vue 挂载时，会把标签的”真身”塞进这个变量。

塞进来的是什么，取决于你把 ref 写在了什么标签上：

  • 写在普通 HTML 标签上 → 拿到真实 DOM 元素
  • 写在子组件标签上 → 拿到子组件实例

8.2 拿 DOM 元素

场景：输入框自动聚焦、ECharts 初始化。第三方库只认原生 DOM，Vue 的虚拟节点它不认识，得把真元素递过去。

⚠️ 必须在 onMounted 之后拿。挂载前元素还没渲染，inp.value 是 null，直接 .focus() 会报 Cannot read properties of null。

场景：父组件要指挥子组件——让弹窗打开、让表单重置、让图表重新 resize。

但——子组件的方法默认是拿不到的。

<script setup> 是个封闭黑盒，父组件即使拿到了实例，上面也空空如也。要子组件自己用 defineExpose 点名开放：

父组件这边 dialogRef.value.open() 才调得通。没写进 defineExpose 的，父组件就是调不到。

这是 <script setup> 故意做的封装，不是 bug。 组件的内部方法属于实现细节，默认不暴露，才能放心重构。想象一下没有这层限制：你把子组件的 open 改名成 show，全项目所有调用它的地方都得改。

对照记忆：Vue2 里没有这层限制，this.$refs.xxx 拿到实例，选项式 methods 默认全挂在上面，直接调。

8.4 什么时候该用

ref 拿实例是”逃生通道”，不是常规武器。判断标准：

  • 能用 props / emit 解决的，别用 ref
  • 需要命令式调用（弹窗 open、表单 validate、图表 resize），用 ref
  • 需要真实 DOM（focus、第三方库初始化、测量尺寸），用 ref

如果父组件在用 ref 频繁改子组件内部数据，那多半是组件边界画错了——该把状态提到父组件，或者上状态管理。

10.3 具名插槽

一个组件有多处要定制（对话框的头部、主体、底部），默认插槽只有一个位置，用 name 区分：

v-slot:名字 简写成 #名字。默认插槽的名字是 default，写 #default 也行，不写就是默认。

10.4 作用域插槽

前三种都是”父传子”，作用域插槽反过来——组件把数据扔出来，使用者决定怎么渲染。

典型场景：封装表格。表格组件负责”有几行、每行什么数据”，但”每列显示什么”只有使用者知道。

<slot :row="item"> 上的属性，会被打包成一个对象传给使用方。使用方用 #default="{ row }" 解构出来——这里解构是安全的，因为它不是响应式数据的解构，是函数参数解构。

⚠️ 一个概念上的纠正：插槽只有”默认插槽”和”具名插槽”两类。作用域插槽不是第三种分类，它是插槽的一项能力——默认插槽和具名插槽都能绑数据往外传。

全局共享 Pinia 见第四篇
任意组件事件 mitt Vue3 已移除 event bus

13.2 props 校验

字段 作用 注意
type 类型 可传数组支持多类型
required 必填 和 default 不同时写
default 默认值 对象/数组必须用工厂函数
validator 自定义 返回 false 触发警告

13.3 v-model 两代对照

Vue2 Vue3
接收 prop value modelValue
通知事件 input update:modelValue
多个绑定 .sync v-model:名字
简写 手写 props + emit defineModel()
版本要求 — 3.4+ 默认可用

类型 组件里 使用时

后备 <slot>兜底</slot> 不传就显示兜底
具名 <slot name="header"> <template #header>

13.5 自定义指令钩子

Vue2 Vue3 时机
bind beforeMount 绑到元素，未入 DOM
inserted mounted 元素已入 DOM
update updated 组件更新后
componentUpdated updated 已合并
unbind beforeUnmount / unmounted 解绑

总结

组件篇的主干六条：

  1. 拆组件的原则：状态往上提，行为往下发。数据放父组件，子组件只显示和喊话
  2. props 是只读的：校验四件套 type / required / default / validator，复杂默认值必须用工厂函数，解构会丢响应性
  3. emit 是喊话：defineEmits 声明事件清单，emit(名字, 数据) 发出去，父组件 @名字 接住
  4. v-model 是一进一出：modelValue 管进，update:modelValue 管出；defineModel 把这两件事封成一个 ref
  5. ref 拿子组件要 defineExpose：<script setup> 是封闭黑盒，不点名的方法父组件调不到——这是封装，不是 bug
  6. 插槽和指令是两个扩展点：插槽开放”结构”，指令封装”行为”
