从零写一个网易云音乐播放器：架构、播放内核与歌词同步

Vue 3 + Vite 的网页音乐播放器。本文记录实现过程中的关键决策和踩过的坑——不是 API 手册，而是「为什么这么做」的取舍记录。

一、项目做了什么

  • 发现页（推荐歌单）、搜索（URL 同步）、歌单详情
  • 播放内核：上下首、进度拖拽、音量、三种播放模式
  • 播放列表抽屉，支持单曲删除
  • 歌词：LRC 解析、逐行高亮、自动滚动、点击跳转
  • 全屏播放页：唱片旋转、封面模糊背景
  • 刷新后恢复播放列表、模式、音量

技术栈：Vue 3（<script setup>）+ Vite + Vue Router + Pinia + 原生 CSS。

数据来自 NeteaseCloudMusicApi。

二、架构：为什么需要两个进程

服务 端口 职责 启动
前端 5173 页面、热更新、代理转发 npm run dev
API 3000 把网易云私有接口包成 HTTP 服务 node server.js

关掉任何一个都会出问题：只开前端 → 请求发不出去；只开后端 → 页面打不开。

面试官 clone 项目时最常见的失败就是只跑了 npm run dev，然后看到白屏。所以 README 里这个警告要写在最显眼的位置。

server.js 是什么

就是一个普通的 JS 文件，作用是「按下启动键」——npm install 只把包下载到 node_modules，不会自动运行。

require 取包，解构出启动函数，调用它。两个参数都可选，不传默认 3000；checkVersion: false 是关掉启动时的联网版本检查（国内网络会卡十几秒）。

后缀的坑：Vite 项目 package.json 里有 "type": "module"，所有 .js 按 ES Module 解析，写 require 会报 require is not defined。

解法 影响范围
文件名改成 server.cjs 只影响这一个文件
删掉 package.json 的 "type": "module" 全局，实测 Vite 构建不受影响

三、跨域：代理到底在做什么

问题

同源策略：协议、域名、端口任一不同就算跨域，浏览器会拦掉响应。页面在 5173，接口在 3000，端口不同 → 跨域 → 控制台一片 CORS 红字。

关键认知

同源策略是浏览器单方面的限制，服务器之间没有这个规矩。

所以可以让浏览器的请求发给同源的 5173，由 Vite 这个 Node 进程在服务端转发到 3000。浏览器全程以为自己在跟 5173 说话。

一次请求，URL 变形两次：

配置 作用
'/api' 拦截以它开头的请求（自己定的约定，不是 Vite 语法）
target 转发到哪
changeOrigin 改请求头 Host，伪装成同源
rewrite 删掉 /api 前缀，还原成真实路径

三个容易踩的点

① 为什么用 127.0.0.1 而不是 localhost

127.0.0.1 是 IPv4 回环地址，硬编码指向本机，不需要解析。

localhost 是域名，得先做 DNS 解析。Node 17 之后改了查询顺序，localhost 可能优先解析成 IPv6 的 ::1。如果服务只监听了 IPv4，请求发到 ::1 就会 ECONNREFUSED——地址看着完全正确，但就是连不上，极难排查。

② /api 不是固定值

改成 /backend 也行，但三处必须一起改：proxy 的 key、rewrite 的正则、fetch 里的地址。

另外别用和页面路由重名的前缀（比如 /search），否则用户点导航时请求会被代理劫持，返回 JSON 而不是页面。

③ 改完必须重启

代理配置在 Vite 启动时建立，不热更新。改完 vite.config.js 不重启，怎么试都是 404。这是新手最常卡的地方。

四、播放内核：audio 与响应式的边界

所有播放能力来自浏览器的一个对象：

决策一：audio 不能放进 ref

ref() 会用 Proxy 包一层来追踪属性变化。但 audio 是浏览器原生对象，属性和方法在原型链上，被 Proxy 包了之后：

  • 高频的 timeupdate 事件会触发无谓的依赖收集，掉帧
  • 某些原生 API 调用时 this 指向错乱
  • 对象身份不稳定

原则：第三方对象、DOM 元素、浏览器 API 实例，都不塞进 ref。只有自己定义的数据才需要响应式。

决策二：audio 必须手动搬运到响应式

audio 不在 Vue 的响应式系统里。 它播了，Vue 不知道，界面不会更新。

这是整个项目最核心的一条认知：Vue 只管它自己管的数据，浏览器对象的变化要靠你手动搬进来。

事件 时机
timeupdate 播放位置变化，每秒约 4 次
loadedmetadata 拿到总时长
play / pause 播放 / 暂停
ended 播完了

决策三：audio 放在 store，不放在组件

如果把 new Audio() 写在组件里，会发生两件事：

  1. 多个组件各创建一个 → 多首歌同时响
  2. 组件销毁时音频被销毁 → 切页面音乐中断

所以它放在 Pinia store 的模块作用域里，全局唯一一份，且不随组件生命周期销毁：

七、歌词：从 LRC 文本到时间轴

输入输出

原始数据是一段带时间标签的文本：

要转成程序能比较的数组：

正则

片段 含义
\[ \] 字面方括号（必须转义，否则 [] 是字符类）
(\d{2,3}) 分钟
(\d{2}) 秒
(?:[.:](\d{2,3}))? 可选的毫秒，. 或 : 分隔

三个细节：

① [] 不转义会变成「挑一个字符」

② ? 只作用于紧邻的一个元素

③ (?: 是分组但不捕获

捕获组编号规则：数左括号，从 1 开始，按出现顺序。 ?: 让外层括号不占编号，内层那个才落到第 3 位。

不多花这一对字符，取出来的就是 '.34' 而不是 '34'，Number('.34') 得到 NaN，整条时间轴全废。

解析

几个点：

为什么用 matchAll 而不是 match

带 g 的 match 只返回匹配到的整串，捕获组会全部丢掉：

matchAll 返回的是迭代器，用 [...] 展开成数组后才能用数组方法。

为什么用 for...of 而不是 forEach

因为里面要 continue。forEach 里不能用 break / continue，也不能 await。

为什么毫秒要 padEnd(3, '0')

.34 表示 340 毫秒，.345 表示 345 毫秒。位数不统一，补到 3 位再转数字。

为什么最后要 sort

一行有多个标签时，生成顺序是文本顺序，不一定是时间顺序（[01:20][00:15] 也可能出现）。而且二分查找的前提就是有序。

为什么统一转成秒

audio.currentTime 就是秒，后面比较时直接对得上。

定位当前行：二分查找

要回答的问题：播到第 t 秒，应该高亮哪一行？

答案是「最后一个 time ≤ t 的行」。t=16 时，0、12.3、15 三行都唱过了，正在唱的是 15 那行。

关键在 lo = mid + 1：命中之后不停止，继续往右试探，直到找不到更靠后的。ans 负责记住最后一个命中的位置。

为什么不遍历：currentTime 每秒变 4 次，100 行歌词就是 400 次比较/秒；二分只要约 7 次。

数据量小的时候差别看不出来，但这是「知道什么时候该优化」的判断。

八、歌词滚动：DOM 测量与 nextTick

为什么需要 DOM 而不是数据

滚动要用 offsetTop、clientHeight、scrollTo，这些只有 DOM 元素有。

所以要在 v-for 里收集每一行的 DOM：

v-for 里没法直接用 ref="xxx" 收集所有元素，用函数形式，Vue 渲染每个元素时会把 DOM 传进来。

注意 :ref 的第一个参数是 Vue 自动传入的 DOM，不是你的数据。 el 只是 element 的缩写。

居中公式

推导：

只滚 offsetTop 的话，这一行会贴到容器顶部；减去一半容器高度才能拉到中间；加上一半行高度是因为 offsetTop 量的是行的顶部，而要对齐的是中心。

为什么必须 await nextTick()

Vue 更新 DOM 是异步批量的：改完数据不会立刻变，等当前同步代码跑完才统一更新（避免连续改十次就重绘十次）。

当前行会加粗放大，高度也变了。不等 DOM 更新就去量 offsetTop，拿到的是变高之前的位置，滚动就会偏。

规则：改完数据要立刻读 DOM，就先 await nextTick()。

一个容易踩的坑

offsetTop 是相对最近的定位祖先算的，不是相对滚动容器。如果容器没有 position: relative，它会一路往上找到 body，算出来的值全错。这是「滚动位置总是偏掉」的最常见原因。

十二、布局：几个 CSS 上的判断

fixed 元素的两个坑

① 宽度不会自动撑满

普通块级元素的 width: auto 是「撑满父容器」，但 fixed / absolute 元素的 width: auto 是收缩到内容宽度（shrink-to-fit）——因为它脱离了正常流，没有父容器宽度可参照。

想让播放条横跨全屏，必须显式指定：

两种写一种，同时写会冲突，浏览器会忽略一个。

② 会盖住内容

fixed 元素浮在上方但不占布局空间，页面滚到底部时最后几行会被遮住。给容器补上等高的 padding-bottom：

任何底部固定栏（导航、工具栏、播放条）都要这么做。

flex: 1 为什么总要配 min-width: 0

  • flex: 1：主轴占满剩余空间，把后面的元素挤到右边
  • min-width: 0：解除 flex 项「最小宽度 = 内容宽度」的默认约束

flex 项的 min-width 默认值是 auto，意思是「不能比内容更窄」。一段不换行的长文本会把最小宽度撑得很大，flex: 1 就压不下去，容器被撑破。

设成 0 之后，才能真正配合 overflow: hidden + text-overflow: ellipsis 把长文本截断成 晴天 - 周杰...。

顺带一提：没设宽高时，flex 项的宽度按内容算，但高度会被拉伸撑满容器（align-items: stretch 的默认效果）。所以「不设宽高就是内容宽高」只对了一半。

行内元素的 width 为什么无效

span、a 默认 display: inline，width / height 无效。实测（都写 width: 100px）：

这叫块化（blockification）——这些场景下浏览器会把元素强制转成块级。

实际用到的地方：想让歌名可点（进全屏页），又不希望整个中间区域都可点。

width: fit-content 让盒子宽度跟着内容走，这是「有个容器要占满，但里面的可点区域要收缩」的标准解法。

十三、Toast：为什么不自己写动画

toast 本意是吐司面包——像面包片从烤面包机里弹出来，冒一下又缩回去。所以 toast 就是「轻提示」：短暂出现、自动消失、不打断操作。

和 alert() 的区别：alert 是阻塞式弹窗，会卡住整个页面；toast 不阻塞。

数组遍历的三种写法

写法 拿到什么 例子
for (let i = 0; i < arr.length; i++) 索引 0, 1, 2
for (const i in arr) 索引（字符串） "0", "1", "2"
for (const item of arr) 元素本身 'a', 'b', 'c'

for...in 遍历的是键名，用在数组上拿到字符串索引，容易踩坑，一般只用于遍历对象属性。

为什么循环里能重复 const：const 是块级作用域，for 每次迭代都是一个新的块。

什么时候不能用 forEach：

for...of forEach
break / continue ✅ ❌
await ✅ ❌ 不会等

只要循环里可能要提前退出，或者要 await，就用 for...of。

sort 的比较函数

sort 会在排序过程中不断挑出两个元素丢给比较函数：

  • a：本次比较的第一个元素
  • b：本次比较的第二个元素

然后根据返回值决定要不要交换这两个元素的位置：

返回值 动作
负数 不交换，a 保持在 b 前面
正数 交换，b 跑到 a 前面
0 不交换

a 和 b 是传入时的顺序（它们在数组里当前的相对位置），所以：

  • a - b 得负数 → 不交换 → 小的保持在前 → 升序
  • a - b 得正数 → 交换 → 大的被挪到后面 → 还是升序

正则：[] 为什么要转义

[abc] 是字符类，表示从里面挑一个字符，不是匹配整个 abc。

所以 [00:12] 会被理解成「0 或 : 或 1 或 2 中任意一个字符」。要匹配字面的方括号，必须写 \[00:12\]。

但 [.:] 这里故意不转义，因为就是要表示「. 或 :」。

正则：转义符的作用范围

字符 作用
^ 匹配开头（零宽断言，不占字符）
\ 转义紧跟在它后面的那一个字符
\/ 字面的斜杠（/ 是正则边界符，必须转义）

^ 不用转义，因为它本来就要当元字符用。\^ 才是「一个 ^ 符号」。

为什么是 ^\/api 不是 ^api：/api/search 开头确实有个斜杠，正则必须一个字符不多不少地描述出来。写成 ^api 匹配不到（开头是 / 不是 a）。

^ 不占字符：/^\/api/ 匹配到的内容是 /api 四个字符，^ 只是附加了「必须在开头」的条件。

正则：match 和 matchAll

正则是规则，不是结果。 要拿结果必须走两步：

为什么要 [...]：matchAll 返回迭代器，能 for...of 遍历，但没有 .length、.map()，必须展开成数组。

为什么不用 match：带 g 时 match 只返回整串，捕获组全丢。

正则：replace 的第一个参数可以是正则

字符串 正则
匹配方式 字面完全一致 按模式匹配
替换几个 只替换第一个 加 g 全部替换
处理多种格式 ❌ ✅

同一个正则两种用途：

matchAll 是「找到并保留」，replace(..., '') 是「找到并删除」。

正则的本质是「描述形状」，不是「指定内容」。

|| 和 ??

|| 把 0、''、false、NaN 都当「假」；?? 只认 null / undefined。

值 v || -1 v ?? -1
0 -1 ❌ 0 ✅
'' -1 ''
false -1 false
null -1 -1
undefined -1 -1

规则：合法值可能是 0 / '' / false 的，必须用 ??。

可选链 ?.

A?.B：A 是 null 或 undefined 时，整体返回 undefined，不往下访问。

只有 null / undefined 会短路。0、''、false 都算正常值，会继续往下走。

三种用法：obj?.prop（属性）、obj?.[key]（动态键）、fn?.()（调用函数）。

@click="fn" 和 @click="fn()" 在 Vue 里等价

两种都是点击时才执行，加括号不会在渲染时触发。

⚠️ React 里 onClick={fn()} 确实会立即执行，因为 JSX 是直接求值。这条坑是 React 的，别套到 Vue 上。

Vue 里唯一需要加括号的场景是要传参：

@seek="player.seek" 为什么不写形参

player.seek 是把函数本身交给 Vue 当处理器，emit 的参数会直接喂进它的形参。

写法 参数能收到吗
@seek="player.seek" ✅ Vue 自动传
@seek="player.seek()" ❌ t 是 undefined
@seek="(t) => player.seek(t)" ✅ 显式接收

只有要加工参数时才写箭头函数，比如 @seek="(t) => player.seek(t + 1)"。

try/catch 必须配合 await

await 是 catch 能接住错误的前提：只有 await 过的 Promise，reject 时才会在当前函数里抛出。

不写 await，rejection 会逃出 try/catch，控制台报 Uncaught (in promise)，而 catch 完全接不到。
