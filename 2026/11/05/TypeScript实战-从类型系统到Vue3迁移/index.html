TypeScript 实战：从类型系统到 Vue3 项目迁移

发表于2026-11-05|更新于2026-11-05|前端语言基础
|浏览量:

这篇不是 TS 文档的中文翻译，是一份「改项目时真正会用到」的筛选版。跳过装饰器、命名空间、JSX、类型体操，只留 7 个能立刻上手的点，每个点配一个真实场景 + 一个易错点。文末附报错速查表和迁移顺序。

一、TS 到底在解决什么问题

一句话：把「运行时才炸」的错误，提前到「写代码时就报红」。

看一段纯 JS：

浏览器里报 Cannot read properties of undefined，你得打开控制台、翻网络面板、对比接口结构，才能定位到「字段名写错了」。

TS 在写这行的时候就会画红波浪线：

所以 TS 的价值不是「多写了一堆类型」，是「错误提前了 30 分钟」。

代价是你要写类型。但下面你会看到，大部分类型是自动推断出来的，真正要手写的只有三处。

二、注解 vs 推断：90% 的类型不用你写

新手最容易犯的错是「每行都写类型」：

这些全是多余的。 TS 看右边就知道左边是什么，这叫作类型推断。

判断标准只有一条：

右边能看出类型 → 不用写；右边看不出（或不该由它决定）→ 必须写。

场景 要写吗 例子
变量初始化为字面量 ❌ const n = 0
函数参数 ✅ function f(id: number)
函数返回值 一般 ❌ TS 能推出来
空数组 / 空对象 ✅ const list = ref<Song[]>([])
API 返回 ✅ request<SongDetail>(...)
对象字面量作为参数 看情况 直接传会被推断成更宽的类型

空数组是必须写的典型：

never[] 的意思是「这个数组永远不可能有元素」，所以 list.push(song) 直接报错。这是新手遇到的第一个莫名其妙的错误。

⚠️ 打开 strict: true 之后，函数的参数是必填的。不传就报错，这比运行时拿到 undefined 好。

三、interface 和 type：怎么选

两个都能描述对象，新手会纠结。判断标准：

描述「一个东西长什么样」用 interface；需要「组合、变形、运算」用 type。

唯一的实质区别

interface 可以重复声明并自动合并，type 不行：

这个特性平时用不上，但解释了一件事：为什么给第三方库扩展类型时只能用 interface（比如给 Window 加字段）。

一个易错点

interface 不能直接写联合类型：

遇到联合类型，只能用 type。

实践建议：项目里统一用一种风格，别一半一半。我倾向对象用 interface，其他全用 type。

四、可选、只读、索引签名

? 和 | undefined 不是一回事

看起来一样，实际差在「能不能省略这个键」：

什么时候用哪个：

  • 接口返回的字段可能没有 → ?（album?: Album）
  • 字段一定有，但值可能是空 → | undefined（currentSong: Song | null）

readonly 只在编译期生效

但它拦不住运行时的修改——编译后 readonly 就消失了。它防的是「你自己手滑」，不是「别人恶意改」。

索引签名：字段名不确定时用

访问 res.anything 都不会报错，类型是 unknown。

⚠️ 索引签名会「传染」：写了 [key: string]: unknown 之后，res.code 的类型也会变成 unknown。除非把 code 显式声明在前面，且类型兼容。

五、联合类型和类型收窄（Narrowing）

这是 TS 里最有价值的部分。 真实数据永远有多种形态，收窄就是「在某个分支里，把宽类型缩小成具体类型」。

基础收窄

四种常用手段：

手段 适用 例子
typeof 原始类型 typeof x === 'string'
in 判断某个属性存在 'error' in res
instanceof 类实例 err instanceof Error
字面量判别 有共同字段的对象 res.status === 'ok'

字面量判别：最常用的一种

关键点：两个分支有共同的字段 status，但值不同。TS 靠这个值判断当前是哪个分支。这叫可辨识联合（discriminated union）。

一个易错点：可选链不能代替收窄

?. 是「访问时不崩」，if 是「收窄类型」。两者解决的问题不同，别互相替代。

另一个坑：if (song) 会把空字符串、0、false 也判成假。如果合法值可能是这些，用 if (song !== null)。

六、泛型：一次定义，到处复用

先看不用泛型会怎样

三份几乎一样的代码，只有返回类型不同。这就是泛型要解决的问题。

泛型的本质：类型也是参数

<T> 是「类型参数」，调用时传进去：

T 不是 any。 any 是「放弃检查」，T 是「先占个位，用的时候再确定」。

泛型约束：限制 T 的范围

K extends keyof T 的意思是「K 必须是 T 的某个键名」。这样既保留了灵活性，又不会传错。

泛型默认值

一个易错点：泛型不会自动推断

函数返回值用了泛型，但调用时没传，TS 只能推断成 unknown（因为没有别的线索）。所以 request<T>() 这个模式，每次调用都必须显式写 <T>。

七、any / unknown / never

三个容易混的类型，判断标准很简单：

类型 含义 能干什么
any 关闭类型检查 什么都能干，包括不该干的
unknown 类型未知 什么都不能干，必须先收窄
never 不可能存在 只能赋值给 never

any 是传染的

any 一旦出现，从这里往下所有类型检查都失效。它不解决问题，只是把问题推后。

unknown 才是安全的「不知道」

原则：接收外部数据（接口、localStorage、postMessage）用 unknown，不用 any。

never 什么时候会出现

或者穷尽检查：

以后给 Mode 加了新值，忘了处理，这个 never 会立刻报错。 这是「让编译器提醒你」的写法。

⚠️ 项目里搜 : any 的数量，是衡量 TS 改造质量最直接的指标。目标：少于 5 个。

八、工具类型：改类型不用重写

TS 内置了一批「把已有类型变个形」的工具。改项目时用得最多的六个：

工具 作用 场景
Partial<T> 所有字段变可选 更新接口的入参
Required<T> 所有字段变必填 —
Pick<T, K> 只保留几个字段 列表项只要部分字段
Omit<T, K> 去掉几个字段 提交表单时去掉 id
Record<K, V> 构造键值对类型 映射表
ReturnType<F> 取函数返回值类型 复用已有函数的返回类型

用在你项目里的具体场景

① Partial —— 更新接口

② Omit —— 提交时去掉服务端生成的字段

③ Pick —— 组件只要部分字段

④ Record —— 播放模式的文案映射

好处：以后给 PlayMode 加一个值，这里会立刻报错，不会漏改。

⑤ ReturnType —— 复用函数的返回类型

一个易错点

Partial 是浅层的，不会递归处理嵌套对象：

要深层可选得自己写，或者用第三方库（type-fest 的 PartialDeep）。大部分时候你不需要，别为这个纠结。

九、keyof / typeof / 索引访问

三个操作符，单独看没什么用，配合工具类型就很有用。

keyof：取所有键名，组成联合类型

typeof：取一个值的类型

注意：在类型位置上的 typeof 和 JS 的 typeof 不是一回事。

JS 的 typeof x 返回字符串 'object'；TS 的 typeof x 在类型位置返回类型本身。

索引访问：从类型里取某个字段的类型

Song[keyof Song] 是「所有字段值的类型组成的联合」，写通用工具函数时常用。

三个一起用的经典场景

这个函数对任何对象数组都成立，而且返回值类型是精确的。 这就是泛型 + keyof 的威力。

十一、迁移顺序：从外往里

顺序错了会到处写 any 糊，改完等于没改。

正确顺序是「从数据往外」：

为什么不能反过来：先改组件的话，组件的 props 类型依赖 Song，而 Song 还没定义，你只能写 any。等后面定义好了，any 已经散落在十几个文件里，改回去的成本比重新写还高。

一个反直觉的点

不要「先写完 JS 版，再整体换 TS」。

整体换是一次性大工程，改到一半容易放弃，而且中间态跑不起来。正确做法是边改边加类型：改一个文件，就给它加类型；遇到 any，就想清楚它本来该是什么。

这样每天都有产出，而且你会真正理解「TS 是用来表达约束的」，不是「加注解的 JS」。

十二、报错速查

报错 原因 解法
Object is possibly 'null' 变量可能是 null 先 if (x) 收窄，或用 ?.
Property 'x' does not exist on type 'Y' 类型上没这个字段 补 interface，或检查字段名拼错
Type 'string' is not assignable to type 'number' 类型不匹配 检查数据来源，别用 as 硬转
Argument of type 'X' is not assignable to parameter of type 'Y' 参数类型不对 看报错里两个类型差在哪
Variable 'x' implicitly has an 'any' type 开了 noImplicitAny，推断不出来 显式写类型
Type 'never[]' is not assignable... 空数组没写类型 const list: Song[] = []
Element implicitly has an 'any' type because expression of type 'string' can't be used to index 用字符串索引对象 用 keyof，或写索引签名
Cannot find module './xxx.vue' 缺类型声明 加 env.d.ts，或装 vue-tsc
'xxx' is declared but its value is never read 变量未使用 删掉，或前缀 _
Property 'value' does not exist on type 忘了 .value ref 在 <script> 里要 .value，模板里不用

tsconfig 里值得开的几项

strict 一次性打开一组检查，新项目必开。老项目迁过来可以先关，改完再开——但别一直关着。
