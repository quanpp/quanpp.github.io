Vue3 核心语法：从模板指令到响应式系统

发表于2026-10-22|更新于2026-10-22|技术
|浏览量:

Vue 系列第一篇。这篇不按知识点清单排，按四层往上走：模板怎么写 → 数据怎么存 → 派生怎么算 → 代码什么时候跑。全程 Vue3 组合式 API，Vue2 只在两代真有差异的地方标一句对照，不写双份代码。学完你会知道：六大指令各自的边界在哪、v-show 和 v-if 差的不只是性能、ref 和 reactive 到底怎么选、为什么解构一下响应性就没了、computed 缓存的究竟是什么、watch 的深浅侦听为什么是反着来的、八个生命周期钩子在组合式里落在哪。文末附四张速查表。

一、Vue 到底解决了什么问题

1.1 先看没有框架的日子

需求很简单：一个按钮，点一次数字加一，超过 10 显示”超标了”。

用原生 JS 写：

数据变一次，界面就得手动同步一遍。现在多一个数据、多一处显示，就多一行同步代码；等页面复杂起来，同步逻辑散落在十几个事件回调里，改个需求要翻五个地方——这就是命令式开发的日常。

Vue 换了个方向：你只描述”数据长这样，界面就长这样”，同步这件事交给框架。

count 一变，{{ count }} 和 v-if 自动跟上，一行同步代码都没写。这是声明式。

一句话记住：Vue 的核心不是指令，是响应式——你只管改数据，视图自己跟上。

1.2 三个关键词

构建用户界面：Vue 只管”数据 → 界面”这一层，不管路由、不发请求、不碰后端。这些都得配别的库，所以它叫”视图层框架”。

渐进式：可以只用它渲染页面上的一个列表，也可以拿它撑起整个后台系统。用多少拿多少，不逼你一次接管全项目。

框架：一套完整的解决方案，有约定好的写法、目录和配套工具。和”库”的区别是——库是你调用它，框架是它调用你。

1.3 Vue3 相比 Vue2，真正变了什么

维度 Vue2 Vue3
代码组织 选项式：data / methods / computed 分开放 组合式：一个功能写在一起
响应式 Object.defineProperty Proxy
新增属性 对象新增/删除属性侦测不到，得用 $set 增删改都能侦测
性能 — 编译期优化、Tree-shaking、体积更小
TypeScript 支持一般 源码 TS 重写，类型推导友好

第一条最影响日常。Vue2 里写”搜索功能”，数据在 data、方法在 methods、监听在 watch，三个地方跳着改；Vue3 里整块写成一个函数，拿走就能复用。

第二条是很多人忽略的实惠：Vue2 里给对象加个新属性，视图不更新，必须 this.$set(obj, 'key', val)。Vue3 用 Proxy 代理整个对象，没有这个坑，$set 也从 API 里删了。

二、起项目：create-vue 和三个关键文件

2.1 创建

会依次问你：要不要 TypeScript、JSX、Vue Router、Pinia、Vitest、ESLint、Prettier。初学建议把 Router 和 Pinia 勾上，其余按需。

Vue2 时代用 Vue CLI（vue create，底层 webpack，启动命令 npm run serve）。Vue3 官方脚手架换成了 create-vue，底层 Vite，启动是 npm run dev。老教程里 npm run serve 跑不起来，不是你的问题。

2.2 从入口到页面

就三步：创建实例 → 挂根组件 → 挂到 DOM 节点。后面装 Router、Pinia，也是在这个链上 app.use(...)。

2.3 一个 .vue 文件长什么样

<script setup> 是个语法糖，编译后会变成 setup() 函数。它带来的三个变化：

  1. 不用写 export default，文件里声明的变量、函数、导入的组件，模板里直接能用
  2. 不用 return，Vue2 的 setup() 得把变量 return 出去模板才认识，语法糖替你做了
  3. 性能更好，编译期就能确定模板用了哪些变量，不用运行时遍历

一个比喻：v-show 是化妆，v-if 是换人。 人一直在，只是化不化妆，那用 v-show；人要不要出场，那用 v-if。

  2. 必须唯一，同一列表里不能重复

第三条最容易犯。为什么不能用 index？看这个场景：

Vue 的 diff 是按 key 比对的。key 从 0,1,2 变成 0,1，Vue 认为”前两项没变，只是少了一项”，于是复用了原来的 DOM，把内容改写成 B、C。如果这些 DOM 里有输入框、有动画、有组件内部状态，就会出现”删了 A，B 的输入框内容还在”这种诡异现象。

用 id 就没这问题：A 的 key 消失了，Vue 精确知道该删哪一个。

3.8 双向绑定：v-model

它只给表单元素用：input、textarea、select、radio、checkbox。写在 div、p 上没有任何意义。

四、修饰符：少写代码的偷懒神器

修饰符是跟在指令后面的”小尾巴”，用 . 开头，把常见逻辑压缩成一个词。

4.1 事件修饰符

修饰符 作用 等价于
.prevent 阻止默认行为 e.preventDefault()
.stop 阻止冒泡 e.stopPropagation()
.self 只有点自己才触发 判断 e.target === e.currentTarget
.once 只触发一次 手动解绑
.capture 捕获阶段触发 addEventListener(..., true)
.passive 不阻止默认行为，滚动更顺 { passive: true }

修饰符能连写，顺序有讲究：@click.stop.prevent 是先停冒泡再阻止默认。

4.2 按键修饰符

常用别名：.enter、.esc、.tab、.delete、.space、.up、.down、.left、.right。

⚠️ 版本差异：Vue2 支持用键码写（@keyup.13），Vue3 把这个能力连同 config.keyCodes 一起删了，只能写别名。老代码里见到 .13 这种，知道是键码就行。

4.3 v-model 修饰符

三个都好记：.number 转数字、.trim 去空格、.lazy 延迟同步。

.trim 在表单里几乎是标配——用户复制粘贴经常带空格，不处理就会搜不到结果。.number 有个坑：它只在输入能转成数字时生效，输入 abc 还是字符串。

六、响应式数据：ref 与 reactive

前面所有指令能”自动更新”，靠的都是响应式。这一节是整篇的地基。

6.1 ref：什么都能装

ref() 返回的不是原始值，是一个带 .value 的包装对象。为什么要包一层？因为 JS 没法监听一个数字变量的赋值，但能监听对象的属性读写。包成对象，才有地方挂 getter/setter。

记住一条：script 里要 .value，模板里不要。

6.2 reactive：只能装对象

reactive() 用 Proxy 代理整个对象，读写属性都会被拦截。它只接受对象（对象、数组、Map、Set），传数字、字符串、布尔会直接失效。

6.3 ref 还是 reactive

ref reactive
支持类型 基本类型 + 对象 + 数组 仅对象类型
访问方式 script 里 .value，模板自动解包 直接访问
整体替换 state.value = {} 可以 不行，会断开代理
解构 会丢响应性 会丢响应性
底层关系 对象值内部靠 reactive 实现 —

日常推荐：默认用 ref。 理由三条：

  1. 不用判断”这个值能不能被 reactive 接”，一律 ref 不会错
  2. 整体替换方便，list.value = res.data 一行搞定；reactive 这么写会断开代理
  3. 团队统一，读别人代码不用猜

reactive 留给一种场景：一个模块级的大状态对象，字段多、结构固定、从不需要整体替换，比如一个表单的十几个字段。

7.2 computed 和 methods 差在哪

同样求总价，写成函数也能跑：

差别在缓存：

computed methods
缓存 有，依赖不变就复用上次结果 无，每次调用都执行
触发时机 依赖变了才重算 每次渲染都重算
模板里写 {{ total }} {{ getTotal() }}

computed 缓存的是”结果 + 依赖关系”：第一次算完把结果存下来，同时记下”我依赖了 list”；下次访问时先看 list 变没变，没变直接返回缓存，变了才重算。

7.4 三个注意

⚠️ computed 里不要写副作用。 不要发请求、不要改别的数据、不要 console.log 当业务逻辑用。它的定位是”算”，不是”做”。要副作用请用 watch。

⚠️ computed 不能和 data / ref 同名。 重名会冲突，Vue 会警告。

⚠️ 依赖必须是响应式的。 如果 getter 里用了普通变量，那个变量变了 computed 不会重算——因为它压根不知道有这个依赖。

一句话判断：能用 computed 表达的，就不要用 watch。

watch 的定位只有一条：响应式数据变化后，去做一件”数据之外”的事——请求、写缓存、改 DOM、上报埋点。

十、实战：小黑记事本

把上面的东西串一遍。需求：

  • 输入框 + 添加按钮，回车也能加
  • 列表渲染，每项可删除
  • 底部统计条数，可一键清空
  • 数据存 localStorage，刷新不丢

逐条对回前面：

代码 用到什么
v-model.trim 双向绑定 + .trim 修饰符
@keyup.enter 按键修饰符
v-for + :key="item.id" 列表渲染，key 用 id 不用 index
v-show="list.length" 频繁切换的显隐，用 v-show
computed(() => ...) 派生数据，不用 watch 算
watch(list, ..., { deep: true }) 副作用（写缓存），且必须 deep
list.value = list.value.filter(...) 整体替换保持响应

两个值得注意的地方：

watch 那里必须 deep: true。 push 和 filter 改的是数组内部，ref 默认浅侦听，不开 deep 存不进去。

key 用 item.id 而不是 index。 删掉第 2 条时，后面的 index 全部前移，Vue 会复用错 DOM，删除动画和输入状态都会错位。

十一、速查表

11.1 指令速查

指令 作用 易错点
{{ }} 插值 只能放表达式，不能放语句
v-text / v-html 渲染文本 / HTML 会覆盖原内容；v-html 防 XSS
v-show 切 display 频繁切换用它
v-if / v-else 创建/销毁 DOM 不频繁切换用它；else 必须紧挨 if
@ / v-on 事件绑定 传参时用 $event 拿事件对象
: / v-bind 属性绑定 冒号后是表达式，不是字符串
v-model 表单双向绑定 只用于表单元素
v-for 列表渲染 key 用 id；别和 v-if 同标签

11.2 ref vs reactive

ref reactive
基本类型 ✅ ❌
对象 / 数组 ✅ ✅
访问 script .value，模板自动解包 直接访问
整体替换 ✅ state.value = {} ❌ 会断开代理
解构 丢响应性 丢响应性
默认 推荐 大状态对象、不整体替换时用

11.3 computed vs watch

computed watch
定位 派生数据 副作用
缓存 有 无
返回值 是 不关心
默认执行 首次访问时算 不执行（immediate 可改）
典型场景 总价、过滤后的列表 发请求、写缓存、操作 DOM

11.4 生命周期对照

Vue2 Vue3 时机
beforeCreate setup 之前 实例创建前
created setup 顶层代码 数据就绪，DOM 未渲染
beforeMount onBeforeMount 挂载前
mounted onMounted DOM 就绪
beforeUpdate onBeforeUpdate 数据变、视图未更
updated onUpdated 视图更完
beforeDestroy onBeforeUnmount 销毁前
destroyed onUnmounted 销毁完

总结

这一篇的主干五条：

  1. 声明式是出发点：不再手动同步界面，只描述”数据 → 视图”的映射关系，这是 Vue 存在的理由
  2. 六大指令是模板层的全部：v-show 与 v-if 按切换频率选、v-for 的 key 用 id、v-model 只给表单用、v-if 和 v-for 在 Vue3 里不能同标签
  3. 响应式只有两个 API：ref 什么都能装、默认选它；reactive 只装对象；解构必丢响应性，要解就用 toRefs
  4. computed 管算，watch 管做：computed 缓存结果、不能有副作用；watch 的深浅侦听在 ref 和 reactive 上默认值相反，这是最易错的点
  5. 生命周期加 on 前缀，created 对应 setup 顶层，且可以写多个、按顺序执行——这是组合式 API 能拆分逻辑的前提
