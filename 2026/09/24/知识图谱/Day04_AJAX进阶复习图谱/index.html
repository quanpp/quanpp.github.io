Day04 AJAX进阶 复习图谱

Day04 AJAX 进阶 · 复习图谱

主线：回调地狱怎么来的 → Promise 链式调用 → async/await 终极解法 → 事件循环原理

一、同步 vs 异步：先分清谁是谁

同步代码

逐行执行，原地等结果再往下走。
例：const a = 1+1、console.log()、变量赋值。

异步代码

调用后不等，继续往下跑，将来完成了再用回调函数通知你。
三大件：setTimeout/setInterval、事件绑定、AJAX请求。
记住这个打印顺序题：
console.log(1) → 同步，先打
setTimeout(...2) → 异步，丢给浏览器计时
document.body.style.background='pink' → 同步
console.log(4) → 同步
结果：1 → 4 → 2（setTimeout 到点后才打）。事件回调更晚——点击一次才打一次 3。

二、解决回调地狱的三代演进（今天的核心主线）面试高频

1
回调地狱（嵌套）：请求省 → 回调里请求市 → 回调里请求区，层层嵌套，缩进像金字塔，改一处牵一发动全身。
2
Promise 链式调用：then() 会返回一个新的 Promise，在 then 里 return 下一个请求，就可以用 .then().then() 平铺展开，不再嵌套。
3
async/await（终极写法）：在 async 函数里用 await 代替 .then()，代码看起来像同步一样从上到下写，实际上还是异步等待。 
// 回调地狱（丑）
axios({url:'/province'}).then(p => {
  axios({url:'/city', params:{pname:p.data.list[0]}}).then(c => {
    axios({url:'/area', params:{...}}).then(a => { ... })
  })
})

// async/await（优雅）——推荐写法
async function getData() {
  const pObj = await axios({url:'/province'})
  const pname = pObj.data.list[0]
  const cObj = await axios({url:'/city', params:{pname}})
  const cname = cObj.data.list[0]
  const aObj = await axios({url:'/area', params:{pname, cname}})
  // 直接用结果，不用 .then
}
await 死规则：① await 必须写在 async 函数里面；② await 后面跟的是 Promise 对象，它会原地等待 Promise 成功才往下走；③ await 只能拿到成功结果，失败要用 try/catch 捕获。

三、try/catch：替代 .catch() 的错误捕获

async function getData() {
  try {
    const pObj = await axios({url:'/province'})  // 报错就跳到 catch
    const cObj = await axios({url:'/city'})
    // try 里某行报错后，后面的代码都不执行
  } catch (error) {
    console.dir(error)  // 错误对象用 console.dir 看详细
  }
}
对比：Promise 写法用 .catch()；async/await 写法用 try/catch。效果一样，都是捕获失败。

四、事件循环 EventLoop：JS 怎么安排代码执行顺序必会

JS 是单线程的，同一时刻只能跑一行代码。那异步代码怎么不卡住？靠事件循环：

① 调用栈（同步代码）
→ 遇到 setTimeout / AJAX / 事件
② 宏任务队列（浏览器管）
setTimeout / setInterval / AJAX完成 / 点击事件
③ 微任务队列（JS引擎管）
Promise.then() 回调
执行规则（背下来）：
1. 先把所有同步代码跑完（调用栈清空）
2. 检查微任务队列，全部清空（一个不留）
3. 取一个宏任务执行
4. 执行完再清空所有微任务
5. 再取下一个宏任务……循环往复
关键：微任务永远比下一个宏任务先执行。

五、经典执行顺序题（自己先做一遍）

console.log(1)
setTimeout(() => console.log(2), 0)
const p = new Promise(resolve => {
  resolve(3)
})
p.then(res => console.log(res))
console.log(4)
答案：1 → 4 → 3 → 2
同步先跑：1、4 打出来。Promise 是微任务，setTimeout 是宏任务。同步跑完后清空微任务队列打 3，然后才取宏任务打 2。
再想一道难的：如果 setTimeout 里面又 new 了一个 Promise 并 .then()，那这个 .then 属于新的一轮宏任务里产生的微任务——等这个 setTimeout 宏任务跑完后，再清空这轮新产生的微任务。

六、宏任务 vs 微任务 对照表

宏任务（浏览器环境）微任务（JS 引擎）
包含setTimeout / setInterval
AJAX 请求完成
DOM 事件绑定
script 整体执行		Promise.then() / .catch() 回调
优先级每轮取一个执行每轮全部清空才走宏任务

七、Promise.all：同时发多个请求

需要同时加载多个接口（比如首页同时显示北上广深天气），用 Promise.all([...]) 合并：

// 同时发 4 个请求，谁先到谁后到无所谓
const p = Promise.all([
  axios({url:'/weather?city=110100'}),  // 北京
  axios({url:'/weather?city=310100'}),  // 上海
  axios({url:'/weather?city=440100'}),  // 广州
  axios({url:'/weather?city=440300'})   // 深圳
])
p.then(results => {
  // results 是数组，顺序和你传入的顺序一致
  console.log(results[0].data.data.area)  // 北京
})
两个要点：① 所有请求都成功才进 then，结果按传入顺序排列；② 任何一个失败就直接进 catch。

八、两个实战案例用了什么

案例核心技术
商品分类先请求一级分类 → 遍历每个 id 发二级分类请求 → 用 Promise.all 合并所有二级请求 → 一起渲染
省市区联动select 的 change 事件；切换省时清空市和区；用 async/await 写请求；submit 时 serialize 收表单 + try/catch 提交反馈
select 下拉框小知识点：select.value 拿到的是选中 option 的 value 属性，不是页面上看到的文字。
