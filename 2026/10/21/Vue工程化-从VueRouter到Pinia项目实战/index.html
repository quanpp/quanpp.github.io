Vue 工程化：从 Vue Router 到 Pinia 项目实战

发表于2026-10-21|更新于2026-10-21|技术
|浏览量:

Vue 复习系列最后一篇。前两篇讲语法和组件，这篇上工程化：Vue3 写法为主，Vuex 压成一节“读旧代码专用”。学完你会知道：Vue Router 4 和 Vue2 时代的写法差在哪、query 和 params 怎么选、全局前置守卫怎么拦未登录、Vuex 四大件一分钟回忆完、Pinia 的 store 怎么写怎么持久化，以及智慧商城和大事件两个项目里值得复用的工程套路。看完这篇就可以开项目了。

一、脚手架：从 Vue CLI 到 create-vue

Vue2 时代 Vue3 时代
工具 Vue CLI（vue create） create-vue（npm init vue@latest）
底层 webpack Vite，开发服务器秒启动
启动命令 npm run serve npm run dev

项目结构和 Vue CLI 时代差不多：src/main.js 是入口，src/App.vue 是根组件，src/router 管路由，src/stores（Pinia 项目）或 src/store（Vuex 项目）管状态。

大事件项目用了 pnpm 建项目（pnpm create vue），比 npm 装得快、省磁盘。包管理器用哪个不影响语法，知道有这回事就行。

2.3 两种传参方式

查询参数 query 动态路由 params
路由配置 不用改 path: '/search/:words'
跳转 push({ path: '/search', query: { words: '黑马' } }) push({ path: '/search/黑马' }) 或 push({ name: 'search', params: { words: '黑马' } })
接收 route.query.words route.params.words
适用 多个参数 单个参数，语义清晰

三个注意点：

  1. query 传多个、params 一般传一个，params 也能传多个但没人这么干
  2. path 跳转不能配 params——用 path 时 params 会被忽略，要传 params 必须用 name
  3. 动态路由参数可以加可选符（/search/:words?），两代都支持

⚠️ 版本差异：通配符语法变了。404 页面 Vue2 写 { path: '*' }，Vue Router 4 要写 { path: '/:pathMatch(.*)*', name: 'NotFound' }。可选参数（:words?）两代通用，不用改。见到老教程的 path: '*' 知道对应什么就行。

2.4 重定向和 404

404 路由必须放最后——前面的规则都不匹配，才轮到它兜底。

2.5 hash 和 history

  • hash（默认）：http://xxx.com/#/home，带 #，不需要服务器配合
  • history：http://xxx.com/home，路径好看，但上线需要服务器配置——用户直接访问 /home 时，服务器上没有这个文件，得配置成一律返回 index.html，否则刷新 404

开发环境 Vite 已经帮你规避了这个问题，所以本地用 history 模式没问题，上线前记得跟后端说要配 history 回退。

三、Vuex 速览（读旧代码专用）

Vue2 项目的状态管理是 Vuex。新项目别用了，直接 Pinia，但公司旧代码里全是它，花一分钟回忆完。

3.1 四大核心概念

概念 干什么 类比
state 存放共享数据 组件的 data
mutations 同步修改 state 的方法 改数据的唯一入口
getters 从 state 派生数据 computed
actions 异步操作，内部提交 mutations 发请求的地方

3.2 三条规矩

  1. state 不能直接改——开启严格模式（strict: true）后，直接 this.$store.state.count++ 会报错。这就是 Vuex 的单向数据流：组件 → actions/mutations → state → 视图
  2. mutations 必须同步——异步代码放进去，调试工具追踪不到变化顺序
  3. 模块化拆分——modules: { user, setting } 按功能拆文件，配合 namespaces: true 加命名空间，访问变成 $store.state.user.userInfo

辅助函数 mapState、mapGetters、mapMutations、mapActions 是把 store 里的东西映射进组件的 computed/methods 的语法糖，展开运算符一撒就行：

智慧商城项目（Vue3 但用了 Vuex）的购物车模块就是标准 Vuex 结构：state 存购物车列表，getters 算总价和全选状态，mutations 改数量，actions 调接口同步。

五、项目套路一：智慧商城（Vue3 + vant + Vuex）

5.1 axios 二次封装

所有项目都封装，套路固定：

API 接口再按模块包一层（api/login.js 里 export const loginAPI = (data) => request.post('/login', data)），组件里只调 API 函数，不碰 request。

5.2 登录态：token 三件套

  1. 存：登录成功，token 存进 Vuex，配持久化（刷新不掉）
  2. 带：请求拦截器里从 store 取 token，塞进请求头
  3. 拦：全局前置守卫判断敏感页面（支付、订单）有没有 token，没有踢去登录页

这一套在 Vue3 + Pinia 项目里一模一样，只是 store 的用法换一下。

5.3 移动端 vw 适配

5.4 其他顺手套路

  • 组件库按需导入：vant 全量导入会把包撑大，配 unplugin-vue-components 自动按需引入
  • 请求 loading：响应拦截器里维护一个计数器，请求开始 +1、结束 -1，页面级 loading 组件统一显示
  • 错误提示统一处理：响应拦截器里判断业务状态码，失败直接弹 toast，组件里不用逐个 try/catch

六、项目套路二：大事件管理系统（Vue3 + Pinia + element-plus）

6.1 请求工具五步设计

要点：响应拦截器里 return res 而不是 res.data，保持链式调用完整，业务失败用 Promise.reject 往外抛，页面里 try/catch 或 .catch 接住。

6.2 嵌套路由搭后台架子

后台系统都是“左侧菜单 + 右侧内容”的 layout：外层一个布局组件，/article、/user 等一级路由指向它，内部再配二级路由，router-view 嵌在布局的内容区。智慧商城的 tabbar 也是同一招。

6.3 代码质量工作流

ESLint 管代码规范（单引号、无分号、行宽 80），保存自动修；配 husky + lint-staged，提交代码时自动检查暂存区文件，不规范不让提交。这套是团队项目标配，比“口头约定规范”靠谱。

6.4 AI 提效

笔记里专门有两节 ChatGPT 和 GitHub Copilot：写提示词让 AI 生成 element-plus 表单/表格代码，人负责审查和改。定位是提效工具不是代写——生成的代码要逐行看懂再提交，尤其是权限和接口部分。

总结

三篇复习文章下来，Vue 的主干全在这：

  1. 语法层：指令两代通用，数据层从 data 换到 ref/reactive，computed 靠缓存，watch 管副作用
  2. 组件层：props 单向流、defineModel 双向绑、provide/inject 跨层、四种插槽、指令钩子改了名
  3. 工程层：Router 4 的 history 写法和通配符语法是两代最大差异；状态管理新项目 Pinia，Vuex 留着读旧代码；axios 封装 + token 三件套 + 路由守卫是所有项目的公共骨架

套路都齐了，开项目吧。
